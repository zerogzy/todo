# todo

Notion 任务管理器的轻量网页入口。支持弹窗新增、读取和完成／恢复任务，展示逾期，使用抽屉侧栏切换待完成、已完成和回收站，并提供只读连接自检。

## 本地运行

使用 Node.js 24 LTS（`nvm use`）：

```bash
npm ci
npm run dev
```

打开 http://localhost:3000。

## 静态检查与生产运行

```bash
npm run lint
npm run build
npm start
```

`npm run lint:fix` 主动修复可自动修复的问题；修改后检查差异并重新运行 lint。构建不要求 Notion Token。

真实环境文件和本地工具缓存不会提交到 Git。`.env.example` 仅包含配置占位符。

## Notion 数据源设置

在 Notion 中准备一个任务数据库，属性名称及类型必须完全匹配：

| 属性 | Notion 类型 | 内容 |
| --- | --- | --- |
| 任务 | Title／标题 | 必填 |
| 完成 | Checkbox／复选框 | 默认未勾选 |
| 截止日期 | Date／日期 | 可选，网页新增只填写 YYYY-MM-DD |
| 备注 | Rich text／文本 | 可选 |
| 任务编号 | Unique ID／ID | 无前缀，原生自动编号，从 1 开始，允许断号、不重排 |
| 优先级 | Select／单选 | 高、中、低；新增默认中 |
| 完成时间 | Date／日期 | 包含时间；网页完成时写入，恢复清空 |

1. 在 [Notion 开发者后台](https://www.notion.so/profile/integrations) 创建内部集成并取得 Token。启用读取内容、插入内容及更新内容能力。
2. 在目标数据库页面的连接设置中添加该集成。集成能访问工作区并不表示它已获准访问此数据库。
3. 获取实际 **Data Source ID**，不要把数据库链接中的 Database ID 直接当作 Data Source ID。可以使用 [Retrieve Database](https://developers.notion.com/reference/retrieve-database) 查看 `data_sources`，从中选定保存任务的那一个 ID；多个数据源时由你明确选择。
4. 在项目根目录创建服务端环境文件：

```bash
cp .env.example .env.local
```

填写 `NOTION_TOKEN` 和 `NOTION_DATA_SOURCE_ID`，修改后重启服务。`.env.local` 被 Git 忽略；`.env.example` 只有占位符。不要给 Token 添加 `NEXT_PUBLIC_` 前缀，不要把真实 Token 放进截图、日志或提交。

API 固定使用 `2026-03-11`；参考 [Database 与 Data Source 升级说明](https://developers.notion.com/guides/get-started/upgrade-guide-2025-09-03)。普通页面和只读自检不会修改数据库属性、页面正文或视图。首次配置已有四属性数据库时，执行 `node --env-file=.env.local scripts/setup-notion.js` 补充缺少的三个属性；脚本先检查冲突，复用兼容属性且不改写已有任务内容，不擅自转换冲突属性。集成需具备更新权限。完成后运行 `npm run check:notion` 检查七属性。代码回退不会删除这些新增属性。

## 使用边界

- Notion 是唯一任务存储。网页新增和完成／恢复；复杂编辑、日历、搜索和子任务管理继续在 Notion 中完成。网页暂不提供删除，回收站菜单仅提供 Notion 管理说明。
- 子任务在网页平铺显示，不展示父子层级。网页排序不自动继承 Notion 视图的筛选或排序。
- 未完成按截止日期升序，无日期在最后；同日按创建时间和页面 ID 稳定排序。已完成在独立菜单中查看，按最后编辑时间倒序，不把它当作完成时间。
- 日期以 `Asia/Shanghai` 判断：未完成且早于今天才逾期，今天到期不逾期。Notion 日期范围取结束日；带时间的数据转换到该时区后按日期判断。
- 完整重新加载页面获取 Notion 外部修改；网页操作成功后自动重读列表，不承诺实时同步或离线写入。
- **没有访问控制或登录。所有能访问部署地址的人都能查看、新增并完成／恢复这个数据源的任务。** Token 留在服务端不代表网页操作受到访问限制。

阶段检查记录见 [docs/stages.md](docs/stages.md)。

## 新增任务

仅在“待完成”点击“添加任务”，在弹窗填写任务标题、截止日期、优先级和备注；已完成与回收站无新增入口。优先级为高、中、低，默认中；截止日期和备注可选。取消、Escape 关闭和切换菜单保留草稿，保存成功清空并关闭弹窗。完整重新加载页面不承诺保留内存草稿。标题去除首尾空白后限制为 1–200 个 UTF-16 代码单元，备注最多 2,000；日期必须为真实的 YYYY-MM-DD。失败保留输入，确认新增成功才清空。

新增不自动重试。若提示“结果未确认”，先刷新检查是否已经创建，避免再次提交导致重复任务；当前表单提交期间不可重复点击，不提供跨窗口去重保证。

勾选复选框保存完成状态，进入侧栏“已完成”后可恢复未完成。保存期间该行禁用，失败保持最后确认状态。同时更新明确的完成值和完成时间，恢复会清空完成时间，重复完成不改写已有时间；保留编号、优先级、备注、日期和正文；多窗口同时修改以最后成功写入为准。标题链接独立打开 Notion。

网页删除暂时撤下，没有删除按钮或可调用的删除 Action。回收站菜单继续提供目标数据库链接和 Notion 回收站操作步骤，不枚举已删除任务、不提供网页恢复或永久删除。

“已保存，列表读取失败”表示 Notion 已确认写入；使用错误区域“重试”，不要重复新增。右上角刷新按钮已移除，外部修改通过重新加载页面获取。安全错误不会泄露 Token 或将读取失败伪装为空列表。

## 界面与开源复用

沿用 MIT Todoist clone 侧栏／内容区代码与普通 CSS，基础控件来自 Water.css 适配；日期使用 react-datepicker 9.1.0 官方示例及包内 CSS。支持现成中文日历、清空和严格 YYYY-MM-DD 手输；日期无效保留原文，不提交旧日期。日期弹层在新增弹窗内，Escape 优先关闭日历。固定来源、完整许可和对应关系见 [docs/third-party.md](docs/third-party.md)。无新 UI 框架、CDN 或字体下载。

## 任务表格与布局

五列表头固定为 **#、截止日期、活动 / 计划 / 任务、优先级、完成情况**，全部居中。日期显示 YYYY/MM/DD，无日期显示 —；编号由 Notion 自动从 1 分配，纯数字、稳定且允许断号，不是列表行号。历史优先级空值只在显示时视为中；未知选项显示未设置，不批量写回。

待完成使用方形复选框，完成后在已完成视图显示“于YYYY/MM/DD HH:mm完成”（上海时间），并可点击恢复。没有真实完成时间的历史任务显示“已完成 · 时间未记录”，不把最后编辑时间当作完成时间。直接在 Notion 勾选不会自动产生完成时间；本轮未配置 Notion 自动化。

页面占满视口，左侧固定导航，右侧为纯白独立滚动区域。内容最大800px、在右侧区域居中；侧栏展开／收起平滑调整剩余空间。表格保持800px，不缩放，窄屏在表格局部横向滚动；手机导航为覆盖抽屉，不挤压表格。

## 测试与 Notion 自检

```bash
npm run lint
npm test
npm run check:notion
npm run check
```

lint 使用 ESLint 官方 Next.js 规则，`npm test` 使用 Node 内置测试且不访问真实 Notion。`check:notion` 只读取数据源属性和一小页任务，不创建、完成或删除真实任务，也不打印任务内容或 Token。

`npm run check` 依次执行 lint、离线测试和 Notion 自检；任何一步失败都会返回非零退出码。缺少 `.env.local` 或授权时自检失败，这是未通过连接检查，不能算作跳过后成功。生产构建不依赖真实连接。

排查时先检查 Data Source ID、集成是否添加到数据库、七个属性的名称与类型；Token 无效或权限不足需要修正服务端配置，限流和网络错误可以稍后重试。不要把原始错误或密钥贴到公开记录中。

## 部署

### Node 生产进程

在有 Node.js 24 的主机检出所需本地提交，安装并构建：

```bash
npm ci
npm run build
npm run check
npm start -- --hostname 127.0.0.1 --port 3000
```

运行前在主机项目目录设置 `.env.local`，或由进程管理器注入 `NOTION_TOKEN` 与 `NOTION_DATA_SOURCE_ID`。不要将密钥写入进程启动参数或 Git。可用 systemd／平台进程管理器保持服务运行，反向代理转发到本地端口，代理请求超时至少 300 秒。`npm start` 不会自动构建。

启动或变更环境变量后重启进程；不需要公开环境变量。先在目标主机运行 `npm run check` 确认其网络能访问 Notion。若使用 HTTP 代理，Node 24 可在启动进程及运行自检时设置 `NODE_USE_ENV_PROXY=1`、`HTTPS_PROXY` 和 `HTTP_PROXY`，不要把开发机代理地址照搬到其他主机。

### Vercel

1. 在 Vercel 导入 GitHub 仓库，或使用 Vercel CLI 从本地目录部署。框架选 Next.js，Node 版本选 24。
2. 在项目环境变量设置中填写 `NOTION_TOKEN`、`NOTION_DATA_SOURCE_ID`，按需分别为 Preview／Production 配置；两者均不加 `NEXT_PUBLIC_`。
3. 安装命令 `npm ci`，构建命令 `npm run build`。不将需要真实凭据的综合 `check` 加入公共 CI。
4. 确认当前套餐／运行模式支持页面声明的 `maxDuration=300`，并将函数时长配置为至少 300 秒，再发起部署。环境变量变更后重新部署。
5. 部署后检查列表，再用专用任务完成下面的验收。本文提供步骤，本次没有向 Vercel 或其他服务器发布。

每个 SDK 请求超时为 15 秒，读取／定值更新最多重试 2 次，每次退避最多 2 秒（单个 API 调用保守预算约 49 秒）；新增禁用自动重试。状态操作路径依次进行页面归属、schema 校验、更新，再重读列表。本轮增加数据库入口读取后，单页数据最坏预算约 294 秒（六个顺序 API 调用），因此给出 300 秒运行预算。多页查询或持续故障仍可能超过平台时限；超大数据源需另行规划分页展示。API 报告 10,000 条截断时应用明确失败，不显示部分总数。

本应用**没有访问控制**：所有能访问部署地址的人都能操作任务。Token 服务端隔离不限制这些访问者。

### 回退

停止生产进程，检出上一可运行提交，重新 `npm ci`、`npm run build` 后启动；Vercel 可回滚到之前的部署。保留服务端环境配置。代码回退不会撤销 Notion 写入，也不会清空任务；误删任务需要在 Notion 回收站恢复。
